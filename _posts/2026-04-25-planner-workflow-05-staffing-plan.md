# 5. 인력 배치서로 TF 구성 요청하기

인력 배치서는 PM이 인력 자원 담당자에게 프로젝트에 필요한 사람을 요청하는 문서입니다. 최초 TF를 구성할 때도 쓰고, 프로젝트 중간에 인력을 추가하거나 교체해야 할 때도 씁니다.

좋은 인력 요청은 “사람이 필요합니다”가 아니라 “어떤 역할이 언제부터 얼마 동안 필요한지”를 분명히 말합니다.

## 작성 시점

| 시점 | 작성 이유 |
| --- | --- |
| 제안 전 | 제안 TF 구성, 견적과 일정 산정 |
| 착수 전 | 실제 수행 TF 확정 |
| 분석/설계 중 | 범위 확대, 전문 역할 추가 |
| 구현 중 | 개발 리소스 조정, 결원 대응 |
| 검수 전 | 품질 점검과 오류 대응 인력 확보 |

## 인력 요청 기본 항목

| 항목 | 작성 내용 |
| --- | --- |
| 프로젝트명 | 공식 프로젝트 이름 |
| 요청 시기 | 제안, 착수, 분석설계, 구현, 검수 등 |
| 요청 구분 | 초기 구성, 인력 추가, 인력 교체 |
| 역할 | PM, 기획, 디자인, 퍼블리싱, 개발, QA |
| 필요 기간 | 투입 시작일과 종료 예정일 |
| 투입 비율 | 100%, 50%, 파트타임 등 |
| 필요 역량 | 도메인 경험, 툴, 기술, 커뮤니케이션 성향 |
| 요청 사유 | 왜 지금 필요한지 |

## 역할별로 요청하기

| 역할 | 요청할 때 확인할 것 |
| --- | --- |
| PM | 고객 커뮤니케이션, 일정/범위 관리 경험 |
| 기획 | 요구사항 정리, 화면설계, 정책 문서화 |
| 디자인 | 브랜드 이해, 디자인 시스템, 시안 제작 |
| 퍼블리싱 | 반응형, 접근성, 브라우저 대응 |
| 개발 | 연동, 관리자, 데이터, 배포 경험 |
| QA | 검수 시나리오 작성, 결함 관리 |

## 성향도 실무 조건이다

인력 배치서에는 기술 역량뿐 아니라 프로젝트에 맞는 협업 성향도 적어야 합니다.

| 프로젝트 상황 | 필요한 성향 |
| --- | --- |
| 고객 의사결정이 느림 | 차분하게 근거를 정리하는 사람 |
| 일정이 매우 짧음 | 우선순위를 빠르게 나누는 사람 |
| 요구사항이 자주 바뀜 | 변경 이력을 꼼꼼히 남기는 사람 |
| 외주사가 함께 있음 | 역할 경계를 분명히 조율하는 사람 |

{: .tip }
사람 이름보다 먼저 역할, 기간, 필요한 역량을 분명히 적어야 합니다. 그래야 배치 담당자가 현실적인 대안을 줄 수 있습니다.

## 다음 글로 이어지는 질문

사람이 정해져도 프로젝트가 안전해지는 것은 아닙니다. 다음 글에서는 수행사와 갈등 없이 중단하거나 조정할 수 있도록 계약 조건을 어떻게 잡을지 정리합니다.
