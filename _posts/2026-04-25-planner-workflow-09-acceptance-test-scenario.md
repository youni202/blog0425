# 9. 검수 시나리오로 테스트를 실행 가능하게 만들기

검수 시나리오는 구현된 기능이 정상적으로 작동하는지 확인하는 방법을 구체적으로 적은 문서입니다.

좋은 검수 시나리오는 담당자가 바뀌어도 같은 방식으로 테스트할 수 있어야 합니다. “회원가입 확인”처럼 막연하게 쓰지 않고, 어디서 무엇을 눌러 어떤 결과가 나와야 하는지 적습니다.

## 검수 시나리오 기본 구조

| 항목 | 작성 내용 |
| --- | --- |
| 검수 메뉴명 | 테스트할 메뉴 또는 기능 |
| 검수 대상 | 일반 사용자, 관리자, 특정 권한 |
| 검수자 | 테스트 담당자 |
| 검수일 | 테스트 날짜 |
| 테스트 ID | 사용할 계정 |
| 검수 경로 | 접근 방법 |
| 검수 항목 | 수행할 행동 |
| 예상 결과 | 정상 작동 시 보여야 할 결과 |
| 실제 결과 | 테스트 후 확인된 결과 |
| 처리 상태 | 정상, 오류, 수정 중, 완료 |

## 경로를 세 가지로 나누기

| 경로 | 설명 | 예시 |
| --- | --- | --- |
| 일반 경로 | 사용자가 보편적으로 이용하는 흐름 | 회원가입 버튼을 눌러 가입 |
| 대체 경로 | 일반 경로 외의 접근 방식 | 이벤트 페이지에서 가입으로 이동 |
| 예외 경로 | 특정 권한만 사용하는 흐름 | 관리자가 회원 상태를 변경 |

## 검수 항목을 구체적으로 쓰기

| 나쁜 예 | 좋은 예 |
| --- | --- |
| 로그인 확인 | 로그인 화면에서 이메일과 비밀번호를 입력하고 로그인 버튼을 눌렀을 때 메인 화면으로 이동한다 |
| 회원가입 테스트 | 필수 약관을 체크하지 않으면 안내 메시지가 표시되고 가입이 진행되지 않는다 |
| 관리자 확인 | 관리자가 회원 상세 화면에서 상태를 변경하면 목록의 상태 값도 동일하게 바뀐다 |

## 예상 결과가 있어야 판단할 수 있다

테스트에서 가장 자주 빠지는 항목은 예상 결과입니다. 예상 결과가 없으면 오류인지 기획 변경인지 판단하기 어렵습니다.

| 검수 항목 | 예상 결과 |
| --- | --- |
| 필수값을 비워두고 저장 | 필수 입력 안내 메시지 표시 |
| 정상 정보로 저장 | 저장 완료 메시지와 목록 반영 |
| 권한 없는 페이지 접근 | 접근 불가 안내 또는 로그인 화면 이동 |
| 이미지 업로드 | 지정된 크기와 형식으로 등록 |

{: .tip }
검수 시나리오는 자세할수록 좋지만, 모든 것을 한 문장에 넣을 필요는 없습니다. 경로, 행동, 예상 결과를 나눠 쓰면 읽기 쉬워집니다.

## 시나리오 작성 순서

검수 시나리오는 화면 순서대로 쓰기보다 사용자 목적을 기준으로 쓰는 편이 좋습니다.

| 순서 | 작업 | 예시 |
| --- | --- | --- |
| 1 | 사용자 유형 나누기 | 비회원, 회원, 관리자 |
| 2 | 주요 업무 흐름 정리 | 가입, 로그인, 신청, 조회, 승인 |
| 3 | 일반 경로 작성 | 정상 정보로 신청 완료 |
| 4 | 대체 경로 작성 | 검색 결과에서 상세로 이동 후 신청 |
| 5 | 예외 경로 작성 | 필수값 누락, 권한 없음, 중복 신청 |
| 6 | 예상 결과 작성 | 메시지, 저장값, 화면 이동, 알림 |

## 회원가입 검수 예시

| 구분 | 검수 항목 | 예상 결과 |
| --- | --- | --- |
| 일반 경로 | 필수 약관 동의 후 이름, 이메일, 비밀번호를 입력하고 가입한다 | 가입 완료 메시지가 표시되고 로그인 상태가 된다 |
| 대체 경로 | 이벤트 페이지의 가입 버튼을 통해 회원가입 화면으로 이동한다 | 가입 완료 후 이벤트 페이지 또는 지정 화면으로 돌아간다 |
| 예외 경로 | 이미 가입된 이메일을 입력한다 | 중복 이메일 안내가 표시되고 가입이 진행되지 않는다 |
| 예외 경로 | 비밀번호 형식에 맞지 않는 값을 입력한다 | 비밀번호 조건 안내가 표시된다 |

## 관리자 기능 검수 예시

| 구분 | 검수 항목 | 예상 결과 |
| --- | --- | --- |
| 일반 경로 | 관리자가 게시물을 등록한다 | 목록에 게시물이 노출되고 상세 화면에서 내용이 확인된다 |
| 일반 경로 | 등록된 게시물을 수정한다 | 수정한 제목과 내용이 사용자 화면에 반영된다 |
| 예외 경로 | 권한 없는 관리자가 삭제 버튼을 누른다 | 권한 없음 안내가 표시되고 삭제되지 않는다 |
| 대체 경로 | 검색 조건으로 게시물을 찾는다 | 조건에 맞는 게시물만 목록에 표시된다 |

## 결과 상태값

상태값은 팀 전체가 같은 단어를 써야 합니다.

| 상태 | 의미 |
| --- | --- |
| 정상 | 예상 결과와 동일하게 동작 |
| 오류 | 예상 결과와 다르게 동작 |
| 확인 필요 | 기획 또는 정책 확인이 필요 |
| 수정 완료 | 개발 수정 완료, 재검수 전 |
| 재검수 완료 | 수정 후 정상 확인 |
| 보류 | 오픈 후 처리하기로 합의 |

## 작성자가 놓치기 쉬운 것

| 놓치는 항목 | 확인 방법 |
| --- | --- |
| 권한별 차이 | 일반 사용자, 관리자, 슈퍼관리자를 나눠 테스트 |
| 빈값과 최대값 | 필수값 누락, 글자 수 초과, 파일 용량 초과 |
| 모바일 화면 | 핵심 흐름은 모바일에서도 별도 확인 |
| 알림/메일 | 화면 동작뿐 아니라 발송 여부도 확인 |
| 데이터 저장 | 화면 메시지와 실제 목록 반영을 함께 확인 |

## 다음 글로 이어지는 질문

검수까지 끝나면 오픈을 준비해야 합니다. 다음 글에서는 데이터 이전 계획서와 오류 리포트로 오픈 전후를 관리하는 방법을 정리합니다.
