# 10. 프로젝트분석서: Project Profile 활용

원본 워드 문서 `05.프로젝트분석서(Project Profile활용).docx`의 내용을 블로그 시리즈 흐름에 맞춰 옮긴 글입니다.

## 이 문서를 쓰는 이유

프로젝트분석서는 Project Profile에서 모은 정보를 실제 수행 구조로 바꾸는 문서입니다. 고객과 프로젝트를 이해하는 것에서 멈추지 않고, 어떤 업무를 어떤 순서로 진행해야 하는지, 어떤 리스크를 먼저 막아야 하는지 정리합니다.

기획자가 이 문서를 쓰는 이유는 제안과 실행 사이의 간격을 줄이기 위해서입니다. 제안서에는 좋아 보이는 말이 많지만, 프로젝트는 역할, 일정, 범위, 산출물이 정리되어야 움직입니다.

## 표를 읽는 방법

아래 표는 Project Profile의 답변을 다시 실행 관점으로 번역하는 과정입니다. 고객 정보는 커뮤니케이션 구조가 되고, 범위 정보는 업무 분장이 되며, 일정 정보는 우선순위와 리스크 관리 기준이 됩니다.

## 18년차 기획자의 메모

제안서가 끝나면 잠깐 안도감이 오지만, 실제 일은 그때부터 시작됩니다. 제안서에 멋지게 적은 범위가 화면설계, 디자인, 개발, 검수 일정으로 쪼개질 때 현실이 드러납니다.

프로젝트분석서는 그 현실을 마주보는 문서입니다. 고객에게 들은 요구를 그대로 옮기는 것이 아니라, 어떤 기능이 먼저 개발되어야 하는지, 어떤 조직과 협의해야 하는지, 어떤 위험이 일정에 영향을 주는지 풀어내야 합니다. 기획자는 제안의 언어를 실행의 언어로 번역하는 사람입니다.
