# 7. 제안 리뷰서로 다음 제안을 더 잘 준비하기

제안 리뷰서는 제안이 끝난 뒤 결과만 적는 문서가 아닙니다. 일정, 전략, 산출물, 커뮤니케이션, 품질 관리, PT 대응을 되돌아보고 다음 제안에서 반복하지 않을 일을 정리하는 문서입니다.

수주 여부와 관계없이 리뷰가 남아야 조직의 제안력이 쌓입니다.

## 프로젝트 개요

| 항목 | 작성 내용 |
| --- | --- |
| 프로젝트명 | 제안 대상 프로젝트 |
| 고객 | 고객사 또는 담당 부서 |
| 프로젝트 기간 | 예상 수행 기간 |
| 사업 규모 | 견적 또는 예산 범위 |
| 프로젝트 구분 | 신규, 리뉴얼, 운영, 프로모션 |
| 운영 대행 여부 | 운영 포함 기간 |

## 제안 개요

| 항목 | 작성 내용 |
| --- | --- |
| 제안 기간 | 준비 시작일과 제출일 |
| 제안 인력 | PM, 기획, 디자인, 개발, 리뷰 담당 |
| 제안 범위 | 제안서, 시안, 견적, 추가 제안 |
| 제안 주안점 | 고객에게 전달하려던 핵심 메시지 |
| 제안 결과 | 제출, 발표, 수주, 탈락, 보류 |

## 리뷰 질문

| 질문 | 확인할 포인트 |
| --- | --- |
| 일정대로 진행되었는가? | 지연된 작업과 원인 |
| 기획 의도가 디자인에 전달되었는가? | 화면 의도, 구성 요소, 우선순위 공유 |
| 제안 전략이 분명했는가? | 전략 도출 주체와 실행 방식 |
| TF 구성이 적절했는가? | 역할, 투입 시점, 멘토링 |
| 내부 커뮤니케이션이 원활했는가? | 공유 누락, 목차 변경, 산출물 취합 |
| 외주 활용이 적절했는가? | 컨셉 전달과 품질 관리 |
| 산출물이 정리되었는가? | 서버 저장, 버전 관리, 재사용 가능성 |
| PT 메시지가 전달되었는가? | 리허설, Q&A, 발표자 이해도 |
| 품질관리는 어떻게 했는가? | 리뷰 기준, 수정 이력, 최종 점검 |

## 총평은 다음 행동으로 끝내기

총평은 “고생했다”로 끝나면 다음 제안에 도움이 되지 않습니다. 다음에 바꿀 행동까지 적어야 합니다.

| 회고 내용 | 다음 행동 |
| --- | --- |
| 전략 도출이 늦었다 | 킥오프 당일 전략 가설을 먼저 작성 |
| 시안 리뷰가 늦었다 | 시안 초안 리뷰 시간을 일정에 고정 |
| 산출물 취합이 어려웠다 | 저장 위치와 파일명 규칙을 제안 첫날 공유 |
| Q&A 대응이 좋았다 | 리허설 후 질문 목록을 표준 산출물로 유지 |

{: .tip }
제안 리뷰서는 비난을 남기는 문서가 아니라 다음 제안의 시행착오를 줄이는 문서입니다.

## 리뷰 회의 진행 순서

제안 리뷰는 기억이 흐려지기 전에 하는 것이 좋습니다. 제출 또는 PT가 끝난 뒤 2~3일 안에 짧게라도 모여야 생생한 이슈가 남습니다.

| 순서 | 질문 |
| --- | --- |
| 1 | 이번 제안에서 가장 잘된 점은 무엇인가? |
| 2 | 가장 늦어진 작업은 무엇이고 이유는 무엇인가? |
| 3 | 고객에게 전달하려던 메시지가 실제 산출물에 반영되었는가? |
| 4 | 역할 배분과 커뮤니케이션에서 막힌 지점은 무엇인가? |
| 5 | 다음 제안에서 바로 바꿀 규칙은 무엇인가? |

## 정량 정보도 남기기

느낌만 남기면 다음에 비교하기 어렵습니다. 가능한 숫자는 같이 적습니다.

| 항목 | 예시 |
| --- | --- |
| 제안 기간 | 5영업일 |
| 참여 인력 | PM 1명, 기획 2명, 디자인 2명, 개발 리뷰 1명 |
| 리뷰 횟수 | 내부 리뷰 2회, 임원 리뷰 1회 |
| 지연 시간 | 최종 제출 2시간 지연 |
| Q&A 수 | 예상 질문 15개 정리 |

## 제안 산출물 보관 규칙

제안이 끝나면 산출물을 찾기 쉽게 남겨야 다음 제안에서 재사용할 수 있습니다.

| 폴더 | 보관 내용 |
| --- | --- |
| 01_RFP | RFP, 질의응답, 고객 제공 자료 |
| 02_Strategy | 제안 전략, 분석서, 회의록 |
| 03_Proposal | 최종 제안서, 발표본, 견적서 |
| 04_Design | 시안, 레퍼런스, 디자인 원본 |
| 05_Review | 제안 리뷰서, Q&A, 개선 사항 |

## 총평 문장 예시

| 관점 | 문장 예시 |
| --- | --- |
| 일정 | 제안 기간이 짧아 전략 도출과 시안 리뷰가 동시에 진행되었고, 최종 취합 시간이 부족했다 |
| 커뮤니케이션 | 역할별 산출물은 도출되었으나 목차 변경이 늦게 공유되어 일부 작업이 중복되었다 |
| 품질 | 핵심 메시지는 전달되었지만 QA와 근거 자료 검토 시간이 부족했다 |
| 개선 | 다음 제안부터는 킥오프 당일 목차와 저장 규칙을 확정하고, 제출 전날 최종 리뷰 시간을 고정한다 |
