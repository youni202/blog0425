# 2. 프로젝트 프로파일로 시작 정보 정리하기

Project Profile은 프로젝트를 시작하기 전에 고객사, 사업 배경, 범위, 일정, 예산, 의사결정 구조를 한 장으로 모으는 문서입니다.

자료가 충분하지 않을수록 이 문서가 더 중요합니다. 모르는 것을 비워두면 “추가 확인이 필요한 항목”이 드러나고, 알고 있는 것을 적어두면 팀 전체가 같은 출발선에서 대화할 수 있습니다.

## 고객사 정보

| 항목 | 확인 내용 |
| --- | --- |
| 회사명 | 공식 명칭과 브랜드명 |
| 위치 | 본사, 프로젝트 진행 장소 |
| 주요 서비스 | 고객사가 제공하는 제품과 서비스 |
| 차별화 요소 | 경쟁사 대비 강점 |
| 주관 부서 | 프로젝트를 담당하는 조직 |
| 담당자 | 실무 담당자와 의사결정자 |
| 연락처 | 이메일, 전화, 협업 채널 |
| 의사결정 구조 | 최종 승인권자와 검토 라인 |
| 투입 인력 | 고객사에서 참여하는 담당자 |

## 프로젝트 정보

| 항목 | 확인 질문 |
| --- | --- |
| 진행 배경 | 왜 지금 이 프로젝트를 하는가? |
| 진행 목적 | 프로젝트가 해결해야 하는 문제는 무엇인가? |
| 사업명 | 내부/외부에서 쓰는 공식 명칭은 무엇인가? |
| 프로젝트 구분 | 신규 구축, 리뉴얼, 운영, 프로모션 중 어디에 가까운가? |
| 진행 범위 | 포함되는 업무와 제외되는 업무는 무엇인가? |
| 진행 영역 | 기획, 디자인, 개발, 운영, 마케팅 중 어디까지인가? |
| 기간 | 제안, 착수, 구축, 검수, 오픈 일정은 어떻게 되는가? |
| 예산 | 공개된 예산 또는 예상 예산은 어느 정도인가? |
| 성공 기준 | 고객이 성공으로 판단하는 상태는 무엇인가? |

## 제안 여부 판단에 필요한 정보

Project Profile은 단순한 고객 소개서가 아닙니다. 제안에 들어갈지, 어떤 전략으로 접근할지 판단하기 위한 기초 자료입니다.

| 항목 | 판단 포인트 |
| --- | --- |
| 업체 선정 방식 | 경쟁 입찰, 지명 제안, 수의 계약 여부 |
| RFP 여부 | 공식 요청서가 있는지, 구두 요청인지 |
| PT 일정 | 제안 발표까지 준비 시간이 충분한지 |
| 선정 우선순위 | 가격, 품질, 일정, 레퍼런스 중 무엇이 중요한지 |
| 파견 여부 | 상주 인력이 필요한지 |
| 운영 대행 여부 | 구축 후 운영까지 포함되는지 |

## 비어 있는 칸을 관리하기

프로젝트 초반에는 모든 정보를 알 수 없습니다. 그래서 빈칸을 숨기지 말고 관리해야 합니다.

| 상태 | 처리 방법 |
| --- | --- |
| 확인 완료 | 출처와 확인자를 함께 기록 |
| 추정 | 추정이라고 표시하고 근거를 적기 |
| 미확인 | 질문 목록으로 분리 |
| 변경 가능 | 이후 확인이 필요한 일정에 넣기 |

{: .note }
Project Profile의 목적은 예쁘게 채우는 것이 아니라, 프로젝트의 불확실성을 눈에 보이게 만드는 것입니다.

## 다음 글로 이어지는 질문

프로젝트 정보를 모았다면 이제 “이 제안을 해야 하는가”를 판단해야 합니다. 다음 글에서는 제안 분석서를 통해 제안의 가능성과 리스크를 정리합니다.
